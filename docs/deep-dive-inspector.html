Inspector Gadget — A Deterministic AI Resolution Pipeline

Inspector runs continuous data-quality checks across the whole inventory — a missing field, an orphaned photo, a relationship that no longer makes sense. What makes it a portfolio centerpiece isn't the checks themselves; it's the three-stage pipeline that turns a detected problem into a resolved one, where an AI model decides what to do but never gets to decide whether it's safe to do it.

1

Detect

Rule-based checks — no AI involved — continuously scan active records against configured rules: a required field left blank, a reference pointing at a record that no longer exists, a duplicate that shouldn't be there. Anything that trips a rule is published as a violation.

2

Enrich Bedrock · Claude Sonnet

An AI agent picks up the violation and investigates — pulling context from across the inventory using a set of read-only tools, the same way a person would dig through related records before deciding what to do. It writes up its reasoning and stages a specific, concrete fix. Critically, the agent never touches the data itself here — it only proposes.

3

Execute deterministic — no AI

A separate, ordinary function picks up the staged fix, runs a set of safety checks against it, and — only if those checks pass — applies the exact change the agent proposed. This function has no model in the loop at all; it's plain code making a yes/no call on a plan someone else already wrote.

Notable decision

The tempting design is to let the AI agent make the fix directly — one fewer moving part. Inspector deliberately doesn't do that. Splitting "decide what to do" from "decide whether it's safe and do it" means every single write to inventory data is made by ordinary, auditable code — never by a model call. The AI's judgment is still the thing that makes the fix smart, but a non-AI gatekeeper is what makes it safe to run unattended.
